# Grounded draft presentation and offline quality gate

Verified release 1.39 implements the [scoped quality plan](GROUNDED_DRAFT_QUALITY_PLAN.md). Reviewed runtime `726bf19ff10d8cd37cb056d70e52b574d37f6cf4` is public on main; [Releases](RELEASES.md) records independent local/cloud/browser/native and Google evidence. This is a deterministic copy repair and a synthetic regression gate, not semantic understanding, a language model evaluation, factual truth verification or permission to publish.

## Reproduced defects and selected contract

The old renderer replaced terminal `?` and `!` with a full stop while recording the original evidence claim. A question could therefore become a statement in the body. A synthetic baseline produced four expected failures/one pass: two punctuation cases, count 45 versus expected base-copy 47, and a direct-message failure incorrectly called social_standard because both share a 1000-unit ceiling.

There were three separate counts: the old presentation metadata summed body/CTA fields, selection reserved one separating unit, and connector previews join nonempty sections with two newlines. The new **base-copy** contract counts trimmed body and nonempty trimmed CTA separated by `\n\n`, in JavaScript UTF-16 code units. This aligns those two fields with ordinary channel preview assembly but excludes headline, hashtags, destination, provider URL weighting and other channel-specific rules. It is not the final sendable message length. Existing exact channel preview and provider guards remain mandatory.

Generation, manual presentation revision and explicit accepted AI-proposal application now use the same fact renderer and base-copy measurement. New generated batches record generator version `1.1.0` and prompt identity `grounded-draft-v2` (the deterministic template identity, not proof of an LLM call). New or revised presentation snapshots record `grounded-copy-v2`. Existing persisted batches, bodies, claims, approval receipts and previews are never rewritten. A revision of historical copy creates a new working successor with its own new presentation contract; the original generation identity still describes its original batch. Ordinary review/approval is still required afterward.

## Runtime symbols and collections

`packages/generation/src/draft-presentation.ts` is a pure module with a type-only domain import, re-exported by the generation package. It has no database, network, clock, randomness, mutable global state or credentials.

| Symbol | Intent |
| --- | --- |
| `GROUNDED_COPY_VERSION` | Constant `grounded-copy-v2` for each newly rendered presentation snapshot |
| `DRAFT_FORMAT_CHARACTER_LIMITS` | Readonly format dictionary: channel_neutral unbounded; social_short 280; social_standard/direct_message 1000; email 4000; article_intro 5000; community_reply 2000 |
| `renderGroundedFact(claim)` | Trims outer whitespace; rejects an empty result; preserves existing recognized sentence-terminal punctuation and optional closing punctuation, otherwise appends a full stop |
| `draftCopyCharacterCount(body, callToAction?)` | Trims both fields, omits empty ones, joins with two newlines and returns UTF-16 length; an empty/whitespace CTA adds no separator |
| `draftCopyPresentation(body, callToAction, format)` | Fresh version/format/count metadata object; includes a characterLimit only for bounded formats |

The renderer's terminal set is `. ! ? 。 ！ ？ ؟ … ।`, optionally followed by any sequence of straight/curly closing quote, apostrophe, guillemet, `)` or `]`. This is a finite presentation rule, not linguistic interpretation or a universal punctuation detector. Interior spaces, line breaks, negation, conditions, question/exclamation marks and source spelling remain untouched. Unsupported endings receive an appended full stop; no source character is removed except outside whitespace. The claim ledger still retains the original complete claim text and evidence IDs, not the presentation-normalized sentence. Blank evidence is already rejected by the approval snapshot contract; the pure helper additionally fails closed.

`draftCopyPresentation` returns `groundedCopyVersion`, `format`, optional `characterLimit`, `characterCount`, `characterCountUnit: "utf16_code_units"` and `characterCountScope: "body_and_cta"`. Counts are recomputed for new manual/AI successors instead of retaining stale generation counts. Unbounded generic copy now records a count without inventing a ceiling. These fields explain rendering; none authorizes a draft or proves factual truth.

Existing generator collections retain their meaning: `depthClaimLimits` controls the six information-depth choices; `callsToAction` maps the seven promotion choices; `usable` excludes unresolved and superseded evidence and sorts by authoritative-context, observed, inferred, then ID; `selected` contains whole claims; `facts` is rendered copy; `claims` retains exact evidence text/IDs plus a separate optional CTA claim. `selectClaimsForFormat` now takes the actual format, derives its ceiling, and uses the same measurement as the reported snapshot. Errors name that selected format rather than reverse-looking-up an ambiguous numeric ceiling. It still stops at the first non-fitting fact, does not skip a higher-priority claim to fit lower-priority copy, and never truncates a fact. No ranking, depth, CTA selection or inferred-evidence review policy changes.

`characterBudgetAudienceName` remains the repository's longest audience name across a batch. Each variant selects against that shared prefix budget; its own actual prefix determines its reported count. This preserves identical factual selections across variants. Brand/audience profiles remain presentation metadata, not a source of new business claims. Existing approval-receipt snapshots, writer locks, exact preparation lineage and AI-artifact/source-version checks remain authoritative.

## Versioned synthetic corpus and evaluator

Evaluation code lives under `packages/generation/src/evaluation`, outside the production entry-point exports. Its imports of generator/domain types are erased. `DRAFT_QUALITY_CORPUS_VERSION` identifies `synthetic-grounded-drafts-v1`. `DraftQualityCase` has a stable `id`, generator `input` and either exact expected body/evidence IDs/optional CTA/ceiling or an exact expected error. `DRAFT_QUALITY_CASES` is a readonly collection of synthetic fixtures; no personal, customer or provider content is uploaded or required.

The corpus currently contains 44 cases: negative/conditional wording; question/exclamation; Japanese/Arabic punctuation and quotes; whitespace; missing terminal stop; authority/ID order; unresolved/superseded exclusion; empty/unusable/blank input; explicit promotion; two audience labels; all six depths; all seven promotion settings; reviewed inferred evidence order; refusing to skip an oversized first fact; two shared-audience-budget variants; exact/overflow boundaries for each of six bounded formats; and CTA separator exact/overflow cases. Generic unbounded format is exercised by the other cases. A coverage test compares the observed format/depth/promotion sets with the declared domain tuples so a future enum cannot silently escape the corpus.

Fixture helpers `fact` and `base` only build explicit data. `profile` is a synthetic audience profile. `formatLimits`, `depthCases` and `promotionCases` are independent expected-value tuples, not imports of implementation mappings. Expected wording/order is explicitly supplied; the oracle does not call production rendering or measurement helpers to calculate its expectations. Repeated `x` payloads exercise size boundaries, not writing quality. An initial CTA boundary fixture mistakenly counted its 20-unit CTA as 19: the gate rejected it, arithmetic was corrected to 258 body + 2 separator + 20 CTA = 280, and no production guard was weakened.

`DraftGenerator` is the synchronous typed pure-generator function contract. `evaluateDraftCase(testCase, generate)` clones input, captures its serialization, invokes the generator twice on independent input copies and accumulates named failures. It requires unchanged input and repeatable output/error. Expected-error cases require the exact error with no output. Successful cases verify title, exact body/CTA, complete ordered claim/citation records, eligible citation IDs, expected count, actual base-copy ceiling, reported ceiling/format/version/units/scope, fact order and absence of invented hashtags/alt text. The result is `{caseId, passed, failures}`; there is no weighted score that lets a safety failure average away.

Important check names are `input_unchanged`, `repeatable`, `expected_failure`, `expected_output`, `headline_preserved`, `exact_body`, `exact_cta`, `exact_claims_and_citations`, `eligible_citations`, `copy_count`, `format_ceiling`, `reported_ceiling`, `reported_format`, `presentation_contract`, `reported_fact_order`, and `no_invented_extras`. Local variables `input`, `before`, `actual`, `repeated`, `expectedClaims`, `copy`, `actualCopy` and `failures` are per-case and never persisted globally. This evaluator expects the typed trusted generator; it is not an arbitrary untrusted model-response parser or runtime authorization gate.

Evaluator self-tests deliberately corrupt wording, remove/change citations, invent a CTA, misreport measurement, mutate input, throw unexpectedly, vary output between calls, return success for expected rejection and exceed the actual ceiling while retaining an acceptable reported count. These must fail. Shared helper tests separately cover the punctuation set/closing marks, blank rejection, whitespace/empty CTA and UTF-16 emoji length. No exact-output fixture establishes whether the approved source itself is true or the copy is useful to a person.

## Commands, integration and acceptance boundaries

Run `npm run qa:draft-quality` from the repository root for a deterministic JSON report containing corpus/generator/prompt identities, scope, total/passed/failed and per-case results. `scripts/qa-draft-quality.ts` maps the corpus through the evaluator and exits nonzero on any failure. It makes no provider or database calls and does not promote a model, change a policy or write a receipt. `npm run check` runs it after tests; the cloud workflow also runs it explicitly. Generation workspace tests cover both the corpus and the evaluator itself. No extra dependency is installed.

Real PostgreSQL integration tests exercise direct generation, General Announcement preparation, manual revision and accepted AI-proposal application. They check generator/prompt capture, preserved question/exclamation text, new presentation metadata/counts and unchanged historical bodies/claims/generation identity. Existing immutable-reference rejection, review, preview and idempotency assertions remain in place. The legacy AI proposal fixture intentionally starts with old full-stop body versus question-bearing evidence: only its newly created successor gets corrected rendering, while its old body and fixture-v1 generation identity remain unchanged.

Rollback replaces code only; never rewrite immutable drafts or delete approvals to restore older formatting. Reverting can restore old presentation defects for future operations and cannot claim v2 rendering for old behavior. New helper behavior should receive a new contract identity when semantics change. Review corpus changes alongside runtime changes; never loosen expected values merely to turn a failure green. Real-provider billing, model quality, content understanding, retrieval quality, human usability and final channel publication acceptance remain separate requirements.
