# Smart Source preparation-preset copy

## Scope and authority

Release 1.31 integrates the immutable 1.30 General Announcement preset library with the existing Smart Source preparation editor. A current owner/admin/editor explicitly browses current-workspace choices, selects a latest saved version, acknowledges replacement, and copies it into the unsaved form. Preview and binding save remain separate actions. This is values reuse, not a durable source-to-preset relationship, workflow-template authoring, automatic preparation, activation or external publication.

Copy preserves the current form's workspace, optional expected binding revision and enabled checkbox. It replaces all reusable settings, including clearing absent Brand/Destination references and replacing—not merging—ordered Audiences. It invalidates an earlier preparation-plan preview. Source synchronization is a different form and is never touched. Existing saved bindings, commands, approvals, Campaigns, drafts, preparation receipts and publication actions are unchanged. Later preset edits do not follow a copied form or saved binding.

## Source map and request flow

`apps/web/src/components/source-preset-picker.tsx` owns the explicit chooser. `source-preset-copy.ts` owns strict choice schemas, acknowledgement identity, exact saved-version validation and pure values replacement. `source-preparation-binding-form.tsx` integrates copying with existing preview/save and immediate conflict guards. `source-preparation-save-result.ts` classifies bounded binding-save responses so an ambiguous outcome cannot unlock another copy or save. Their adjacent tests cover those contracts; `server/source-preset-choices-route.test.ts` covers the new route.

`GET /api/v1/preparation-presets/choices?workspaceId=<UUID>&page=<1..2000>` accepts exactly one workspace and at most one page (default 1), and rejects unknown/repeated query keys, non-decimal/leading-zero/scientific/negative/out-of-range pages. It canonicalizes the workspace UUID, requires current write access, calls the existing membership-scoped `PreparationPresetRepository.list`, and returns a minimized no-store page. It does not accept source identity or grant permission to configure any source. Source permissions are checked independently by existing preview/save operations.

The list contains at most 50 latest-version labels, including archive state. It is an offset-based current view ordered by the existing repository, not a stable cursor snapshot. Concurrent edits may move records between pages; refresh restarts at page 1 and clears selection/consent. `more` is a lookahead, not a total. Page 2000 is a hard browsing limit; when `more` remains true, the UI explicitly says the library is not complete. Archived options are disabled. No configuration, notes, canonical request, actor, private request ID, hash, timestamp or credential is delivered in this chooser response.

Copy calls the existing readonly `POST /api/v1/preparation-presets/<id>/copy-settings` with exact `{workspaceId, expectedRevision, versionNumber}`. Its 1.30 configured-Origin, current-writer, root revision/archive, current profile/policy and transaction rules remain authoritative. It creates no receipt, audit or execution records. The browser additionally validates exact workspace/preset/version and the strict saved-version schema before applying values. A stale root, retired reference, unavailable profile or invalid response leaves the form values and earlier preview unchanged. Refreshing choices is an explicit recovery action; the client never silently retries or substitutes a newer version.

## Data, fields, constants and collections

`SourcePresetChoice` is a closed object: `id` identifies the preset root; `revision` is the observed optimistic library precondition; `versionNumber` selects the immutable settings version; `title` is display-only; `archived` disallows copying. `SourcePresetChoices` adds exact `workspaceId`, requested `page`, boolean `more`, and ordered `items`. Both exported Zod schemas reject unknown keys. The module-local `uuid` and `revision` schemas constrain UUIDs and positive signed-32-bit revision/version numbers; they are validation definitions, not mutable application state.

Limits are page 1–2000, at most 50 choices, title 1–120 characters and revision/version 1–2,147,483,647. The duplicate-root refinement constructs a temporary `Set` of item IDs. It rejects a page with duplicate choices; it does not reorder results. Selection uses the root ID, but consent binds the full validated selected object and exact workspace/source scope using `sourcePresetSelectionKey` and deterministic JSON serialization. Changing root, title, revision, version, archive state or either scope ID changes that key.

`copySourcePresetValues(current, configuration)` parses the existing strict `presetSettingsSchema` and constructs a new object. Only `current.workspaceId`, optional `current.expectedRevision` and `current.enabled` survive from old authority/control fields. Settings are `templateKey: general_announcement`, `templateVersion: 1`, name, description, optional Brand version, ordered Audience versions, optional Destination, information depth, promotional strength and timezone. The settings schema rejects injected workspace, writer, binding revision, enabled, steps or other execution fields. Zod parsing creates fresh settings/array objects; the prior form and input array are not mutated. Optional references absent from the preset disappear from the replacement. An empty description replaces old text. Audience order remains authored order; no selections means the existing General fallback. All existing server normalization, uniqueness, current-publication and ceiling checks still apply.

`parseSourcePresetChoices(value, workspaceId, page)` validates a strict page then rejects a response for another request. `parseSourcePresetVersion(value, workspaceId, selected)` validates the existing saved-version DTO and checks exact workspace, root and immutable version; it also rejects an archived selection. The root revision is checked server-side because immutable version DTOs do not carry current root state. The response is data from an authenticated endpoint, not a signed capability or independent approval.

The shared `readPresetResponse` bounds each choice/copy/save-confirmation body at 65,536 bytes, including error bodies, checking both Content-Length and streamed chunk totals. It stores bounded `Uint8Array` chunks, counts length, assembles bytes once, decodes strict UTF-8 and parses JSON. Oversized streams are canceled; reader locks are released. `presetPayloadData` extracts unknown data for subsequent validation. `presetErrorMessage` uses only a bounded message under 1,000 characters or a fixed fallback. Raw provider/SQL exceptions never become chooser errors.

## Browser state and lifecycle

| Owner | Important variable | Intent and lifetime |
| --- | --- | --- |
| Picker | `choices` | Last validated page for this mounted editor; undefined until explicit browse or after a failed read. |
| Picker | `selectedId` | Explicit chosen root; empty after load/refresh/page change, never automatically selected. |
| Picker | `acknowledgement`, derived `key`/`acknowledged` | Consent for the exact selected version/revision and workspace/source, not a generic boolean. Cleared on selection/page changes and successful copy. |
| Picker | `selected` | Derived matching choice from the current page, never a separate stale object cache. |
| Picker | `pending`, `error` | Local read/copy progress and bounded error display. They grant no authority. |
| Picker | `inFlight` ref | Synchronously rejects duplicate browse/copy handlers before React state renders. Released in `finally`. |
| Picker | `mounted`, `controller` refs | Suppress obsolete completion updates and abort its readonly choices fetch on unmount. |
| Source form | `binding`, `values`, `preview` | Existing confirmed binding, unsaved proposal and optional server-normalized preview. A successful copy changes only values and clears preview. |
| Source form | `pending` | `copy`, `preview` or `save`; disables conflicting preparation controls while the operation runs. |
| Source form | `saveUncertain` | Locks all preparation editing/copy/preview/save until a full current-state reload after an ambiguous binding write. |
| Source form | `inFlight`, `mounted`, `copyController` refs | Immediate copy/preview/save exclusion; no late UI/navigation updates after unmount; abort obsolete readonly copy fetches. Binding writes are not canceled or interpreted as rolled back. |
| Source form | `error`, `message` | Failure or outcome explanation. Successful copy explicitly says no binding was saved and enablement/revision stayed unchanged. |

`load(page)` clears selection and acknowledgement before reading. Choices loading can overlap local field editing because it never applies settings. The parent disables the chooser during copy/preview/save or uncertain recovery. `copy()` requires a nonarchived explicit choice, matching acknowledgement, enabled controls and no local in-flight operation; its parent callback independently checks writer eligibility and the parent operation guard. Thus an intermediate render does not permit a second conflicting copy or save. The picker catches unexpected callback failure and does not claim success.

The source page's existing workspace/source/version/binding-revision key remounts the form for refreshed authoritative props. The nested picker also keys on those identities and the latest confirmed local binding revision. Unmount aborts only readonly choice/copy work; the server may have already handled a request, but these endpoints do not mutate settings. Save and preview completion now check mounted state before UI updates; an in-flight save can still commit after navigation, so subsequent pages must read current state. No shared browser cache, local/session storage, cookie, worker, timer or new mutable global is introduced for source copying. Existing server repository caching/error branding and database pool configuration remain as documented for the 1.30 library.

## Binding save ambiguity and recovery

`SourcePreparationSaveResult` has three outcomes. `saved` contains an existing scope-validated binding view; `rejected` contains a bounded message for a parsed definitive non-5xx denial; `uncertain` contains a message when a 5xx response, missing/invalid/oversized/invalid-UTF-8 body, wrong workspace/source or malformed success prevents confirmation. Network/request exceptions are also uncertain. Tests explicitly distinguish 401/403/409/422 from 500/503 and invalid bodies. No automatic resend is performed.

An uncertain result sets `saveUncertain`, clears preview and displays **Load current settings before continuing**. All preparation fields and copy/preview/save actions remain disabled. **Reload current source settings** performs a full reload to discard the unsaved proposal and load the latest server binding/revision. The warning explains that an earlier save may have succeeded and that existing queued work is not changed. It is not an idempotent write-recovery receipt: source binding save continues to use its existing revision precondition, and no new receipt/schema is invented. Definitive rejection preserves the proposal for correction; a revision conflict still requires fresh authoritative state before a successful retry.

Do not resolve uncertainty by resetting enablement, deleting commands/receipts, automatically retrying a different request, or substituting another preset. Never treat timeout or aborted UI navigation as proof a binding write failed. Copy itself is readonly and can be explicitly repeated after review, but an uncertain binding write takes precedence over copying.
