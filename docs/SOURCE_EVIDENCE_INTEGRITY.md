# Source-evidence integrity

Release 1.40 implements the [bounded plan](SOURCE_EVIDENCE_INTEGRITY_PLAN.md). Runtime `af80a2849e67909327678617d08b4e1a38c524d7` is public on main and passes both exact-source cloud gates, including 3,109 tests/169 files, 44/44 quality cases and both clean audits. Final Google development-tab readback passes; [Releases](RELEASES.md) separates cloud, local, native and browser evidence. This is whole-text admission with explicit review, not semantic extraction, source-truth assessment, OCR or automatic summarization.

## Why the behavior changes

The old ContentPackageService created an observed file-name/path claim and a second observed claim from extractedText.slice(0, 500), each with confidence 1. A suffix or Unicode pair could be severed. Known partial text was still observed evidence: needs_review alone did not block exact approval. Six pre-fix service regressions reproduced five failures/one pass. New ingestion no longer turns transport identity into a marketing fact or promotes a prefix as a complete extraction. It preserves the existing asset's captured text and creates one source evidence row: exact admitted text or an unresolved review instruction.

## Admission contract and variables

`packages/ingestion/src/source-text-evidence.ts` is a pure internal module, not re-exported from the package entry point. It performs no I/O, authorization, randomness, clock reads or mutation. All result objects/arrays are fresh per call; there is no mutable global cache. `SOURCE_TEXT_EVIDENCE_VERSION = source-evidence-v1` identifies the assessment, independently of app 1.40.0 and generator 1.1.0/grounded-draft-v2. `SOURCE_TEXT_EVIDENCE_MAX_CODE_UNITS = 500` retains the prior automatic bound but applies it to the whole trimmed extraction, never a prefix. This is not a byte limit, source size limit, manual-correction limit or destination character budget.

`SourceTextEvidenceInput` contains extractedText, extractionStatus, optional extractionError and optional readonly metadata. The status uses the media processor's completed/skipped/failed union. `incompleteDiagnostic(metadata, key)` permits absence of the named diagnostic (the existing plain-text contract); a present documentExtraction or textExtraction must be a non-array object with state exactly completed. Null, missing state, malformed values and unknown states fail closed. It does not inspect unrelated metadata, guess parser completeness or infer source truth.

`assessSourceTextEvidence(input)` trims only the exterior of its local text value. Interior whitespace, punctuation and Unicode remain unchanged. It evaluates all independent reasons in the following stable order; no aggregate score can hide one reason.

| SourceTextReviewReason | Condition |
| --- | --- |
| extraction_not_completed | status is not completed |
| extraction_error | the extractor reported nonblank error/diagnostic text |
| document_incomplete | present documentExtraction does not explicitly report completed |
| text_incomplete | present textExtraction does not explicitly report completed |
| empty_text | missing or whitespace-only captured text |
| automatic_limit_exceeded | trimmed text.length exceeds 500 UTF-16 code units |

`reviewMessages` is a readonly reason-to-explanation dictionary; it contains no user/provider text. `reasons` is an ordered per-call array. `reviewRequired` is reasons.length > 0. Admitted `claim` is the entire trimmed text with provenance observed. Otherwise claim is a diagnostic instruction, explicitly not a factual claim, with provenance unresolved. It never copies a partial source prefix or untrusted extractionError into that instruction. Source errors remain visible separately in captured asset data.

`metadata` is version, state (whole_text/review_required), characterCount, characterCountUnit=utf16_code_units, automaticCharacterLimit and reasons. The count measures trimmed extracted text, not the diagnostic instruction. `whole_text` means the entire available extraction passed this bounded contract, not that the original document was parsed flawlessly. Parser-reported completion and existing decoding behavior remain separate limitations.

## Ingestion data flow and preserved boundaries

ContentPackageService performs its existing bounded source download/object-store read/hash check and optional media processing. After extraction or its caught failure, `sourceText` holds the assessment of the original asset. The per-package `observed` array now begins with one generated-ID row containing that result, exact source-item/content-hash references, and factKey=source.text_review only for unresolved text. Admitted observed text retains existing confidence 1; unresolved instructions have no confidence. These numbers are not a truth probability. The package's legacy average over supplied confidence values is unchanged and can include contextual values; it is not an overall readiness or truth score.

The original asset receives `metadata.sourceEvidence`; a fallback original gets the same field. Derivatives do not receive a fabricated independent assessment. Existing metadata fields, full captured extractedText, status/error, contentHash, object keys, byte sizes, scan state, rights and accessibility remain intact. File name/path/provider identity remain asset provenance. If extraction did not read bytes, the preexisting fallback asset hash is an identity hash, not proof of a byte download. Unresolved evidence still blocks factual use.

Structured Context Pack resolution and readiness diagnostics are unchanged and append their existing evidence/conflicts. `sourceText.reviewRequired` participates in the saved needs_review status alongside existing context, readiness, media, scan/accessibility and extraction checks. More importantly, active unresolved evidence makes the existing effective-evidence-v1 evaluator return no usable IDs and blocks exact approval. Context facts cannot make that unresolved source item disappear. Unsupported images/documents or missing text now require source fact review even if other context is available; this deliberate behavior replaces the old transport-only fact fallback.

## Explicit review, authority and history

The existing package UI shows the unresolved instruction, approval blocker and complete captured asset text in an expandable panel. “Complete captured” means everything stored, not a promise that the source was completely extracted. Browser acceptance found the list coerced SQL-null confidence to 0%; its server rendering now labels both null and undefined Unavailable, preserving real zero/other numeric values. Eight page tests cover this distinction and current-user/workspace scoping; no score is fabricated or reinterpreted. For partial/failed sources, inspect the original before asserting a fact. A current owner/admin/approver may record a 1–5000-character reviewed correction via the existing version/fingerprint-guarded operation. Editors cannot correct or approve source facts. The operation records an authoritative successor plus learning review/proof/audit; only the old row's superseded pointer changes, while its original diagnostic/provenance/references remain history. Its successor references the learning review; the proof links back to the exact source review. Do not change this to an unreviewed automatic summarizer.

Correction does not approve the package. Exact package approval is a separate explicit action; draft preparation rechecks that current receipt and selects only effective evidence. Draft approval, finalization, provider execution and publication remain separate. A manual correction can exceed an eventual draft format's limit; the existing whole-claim generator then rejects a no-fit result instead of cutting it. There is no automatic retry of a correction, approval or provider action.

No migration, data backfill, credential, environment variable or dependency is introduced. Historical packages, evidence, assets, approved snapshots, generations and drafts are not relabeled or rewritten. Deploying or rolling back code changes future ingestion only. Operators must explicitly review older potentially truncated evidence under their normal data/review policy; this release is not historical remediation. Re-ingestion retains its existing version/invalidation behavior.
