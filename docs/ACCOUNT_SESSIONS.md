# Personal Market Me sign-in session controls

Release 1.51 is verified and published: runtime `bbf84bf893c521b9cabc4f1fc58cf9247da674bf` passes final local/native, unsigned packaging, isolated browser/production, independent exact-source feature/main cloud gates and final Google readback. See [Releases](RELEASES.md) for separate evidence. This implements only own-account application sessions from specification 02/18 and the open implementation-matrix session-control gap; it does not complete the application.

## Scope and integration

Settings separates the current session from other active sessions. Other sessions are sorted newest-created first in30-record keyset pages with an exact decimal-string total. Users review one selected public session ID and recorded timestamps, then explicitly confirm its sign-out. Current-session Sign out stays unchanged. No browser/device/IP/location metadata is invented or collected. Last seen is a server request timestamp, not human attention. Ending one Market Me session neither logs out of an OIDC provider nor revokes provider, companion or service credentials. Already-authorized in-flight work may finish; subsequent authentication fails after deletion commits.

Database source: `account-session-models.ts`, `account-session-repository.ts`, their model/live tests and public index exports. Forward migration0124 is additive. Web source: `server/account-session-auth.ts`, `account-session-api.ts`, `app/api/v1/account-sessions/route.ts`, `components/account-session-contract.ts`, `account-sessions-section.tsx`, `account-sessions-panel.tsx` and its scoped CSS. Settings accepts only an optional bounded sessionCursor query. Its preexisting workspace requirement remains; the own-account API requires no workspace role or membership. The shared SQL bundle has28 lazy repository getters and stores no actor data. Readiness requires124 migrations ending0124. No new dependency/environment variable/credential is introduced.

## Schema and lifetime

`app_session.session_id` is a fresh random UUID default for existing and new sessions, with a unique index. It is a public opaque identifier, not a bearer token or authority. A new `(user_id,created_at DESC,session_id DESC)` index supports paging. Migration leaves existing token_hash,user_id,created_at,last_seen_at,expires_at values untouched. A guard prevents subsequent identity changes to session_id,user_id,token_hash,created_at while permitting established last-seen/expiry lifecycle updates and deletion. Existing authentication still addresses the original token hash; sessions do not rotate at migration.

`account_session_receipt` columns:

| Column | Intent and lifetime |
| --- | --- |
| account_id | Own account FK; account-deletion cascade; first half of primary key. |
| request_id | Caller-generated UUID identifying one exact intent; second half of primary key. |
| target_session_id | Public ID of the one removed session, retained without an FK to that deleted row. |
| actor_session_id | Public ID of the originating caller, not a token/hash; differs from target. |
| revoked_at | Database clock timestamp for the original successful outcome. |
| canonical_request | At most2048 UTF-8 bytes of fixed-order exact JSON for replay equality. |

Canonical JSON has exactly accountId/requestId/targetSessionId, each an actual matching JSON string. Insert requires the target to be absent and the originating session to belong to this account. Receipt updates/direct deletion fail while the account exists; deleting the account may cascade them. These integrity guards do not authenticate arbitrary trusted SQL or establish a new retention policy. Account audit actor SET NULL retains historical audit data under existing lifecycle behavior; no account-erasure workflow is added. Backups/restores can affect historical receipts and sessions and must be covered by ordinary operations policy.

## DTOs, constants and normalization

Frozen `ACCOUNT_SESSION_LIMITS` has pageSize30,requestBytes2048,cursorLength512. `AccountSessionView` contains only sessionId,createdAt,lastSeenAt,expiresAt. `AccountSessionSnapshot` adds accountId,observedAt,current,others,totalOthers,nextCursor. `others` is a readonly array of at most30; current is separate and never a revocation button. Public timestamps are ISO UTC at JavaScript millisecond precision; internal keyset ordering preserves PostgreSQL microseconds. totalOthers remains an exact decimal string rather than a rounded number.

`AccountSessionRequest` is accountId/requestId/targetSessionId. `AccountSessionReceipt` adds only revokedAt. `AccountSessionActor` is server-internal accountId/tokenHash and must never be serialized, logged or passed to a client component. `AccountSessionCursor` is at/id. Error codes are invalid_input,access_denied,authentication_required,not_found,request_conflict,current_session; a Symbol.for brand plus Error check recognizes module-reloaded errors, not arbitrary name/code objects. This is not a sandbox against malicious in-process code.

`accountSessionUuid` validates canonical hyphenated UUID version1–8/standard variant, lowercases and never trims. `normalizeAccountSessionRequest` requires an ordinary object, inspects all descriptors before value reads, rejects accessors/hidden/symbol/unknown fields and returns a frozen fixed-order request. No browser-supplied token/hash/current-session flag/actor/role/workspace hint is accepted.

Cursor encoding uses canonical base64url JSON `{v:1,at,id,context}`. at is exact six-fraction-digit UTC, calendar/time checked without replacing it with rounded Date output. SQL binds cursor time as `::text::timestamptz`: a directly timestamp-typed parameter would invoke the driver's Date serializer and round microseconds. A regression now verifies the database really holds two distinct adjacent-microsecond groups before checking30/30/5 paging. context is SHA256 over a domain string, account UUID and current-session public UUID. Decode validates length/alphabet/canonical encoding/fatal UTF-8/exact keys/version/time/context. This digest binds a paging selection, not authorization or a secret signature; changing account or current session invalidates it. Every read still checks the actual cookie-derived token hash against the current database.

## Reads, locks and atomic revocation

`selfScope` normalizes and compares account hint to independently authenticated actor before SQL, then checks the server-only SHA256/base64url hash shape. This blocks stale account-A forms from touching account B. The browser cannot construct authority by knowing a public session ID.

`list` first privately resolves the current session ID for cursor context. Its next statement independently revalidates account/hash/current ID and expiry, then uses materialized auth/others CTEs with one statement-time snapshot, exact total and31-row lookahead. It returns current separately,30 visible other rows and an optional cursor from the last visible microsecond key. No current/expired/foreign session enters others. No cached authority, UPDATE or last-seen touch occurs inside this repository method; the outer normal authentication lookup may update last_seen_at. Lists are live observations, so concurrent additions/deletions can alter coverage between pages; no frozen-history promise is made.

`getReceipt` uses a current unexpired session join and an actor-private exact receipt LEFT JOIN. Missing current authority throws authentication_required; a missing receipt is undefined, not evidence a pending action failed. It is read-only and exposes no directory of other account/request identities.

`revoke` canonicalizes once, starts a transaction and locks app_user FOR UPDATE. That account lock serializes mutual revocations, profile saves and account deletion. It then locks current/selected own session rows in public-ID order. Crucially it rechecks current-session existence and expiry against clock_timestamp AFTER potentially waiting locks, not transaction-start now(). Current-self target fails with guidance to use existing Sign out. Exact prior request bytes return the original receipt before checking whether the target still exists; changed bytes conflict. A later currently authenticated session of the same account can retrieve/replay history.

For a new request, DELETE binds exact account/target, requires target still active and current session still active at the decision. Foreign,missing,expired or independently removed targets produce the same not_found outcome and no invented receipt. The transaction inserts the immutable receipt and `account.session_revoked` audit, subject_type account_session, subject_id selected public ID, actor_user_id own account, null organization/workspace. Audit data is requestId/actorSessionId/targetSessionId only. Failure of receipt/audit rolls deletion back. No token/hash/email/device data enters these records.

Repository account/cursor/context/rows/first/others/visible/last/request/canonical/current/prior/removed/saved are method/transaction locals. ReceiptRow retains internal canonical JSON only for equality and Date|string database time; explicit mapper emits only public fields. SessionRow never selects token hashes into output. Mutual requests cannot both succeed from stale authority: the first account lock winner removes the losing caller, which fails its post-lock revalidation. Ordinary logout deletes only one session row and does not wait for the account lock; tests cover revoked callers and session-row waits.

## Authentication and HTTP boundaries

`requireAccountSessionActor` reads mm_session through server cookies once, hashes via existing hashOpaqueToken, validates through existing getSession and returns only an internal actor context. Missing/expired/revoked cookies raise AuthenticationError. Raw tokens never leave this helper. Existing session creation, seven-day cookie settings, OIDC/development login and current logout are unchanged by this increment.

POST requires exact configured Origin, no query, current session, application/json and at most2048 advertised/streamed UTF-8 bytes. Fatal decoding and syntax parsing precede duplicate-member detection, including escaped aliases; the strict normalizer rejects nested or additional fields. Routes independently compare account hint before constructing repository work. New successful revocation returns201 `{data:receipt,meta:{replayed:false}}`; exact replay returns200 with replayed true. No-op/absent-target success is invented.

GET permits exactly one accountId and either optional cursor for the live list or optional requestId for historical lookup, never both; duplicates/unknown keys fail. Public responses are private,no-store, Vary Cookie, nosniff and never change cookies. Frozen MESSAGES supplies bounded public text. Status mappings:401 expired/anonymous,403 origin/foreign account,404 absent outcome,409 changed key/current target,415 media,413 bytes,422 shape/cursor and503 unknown storage failure. Raw exceptions/authentication details are not logged or echoed. Ordinary access logs may include public account/request/cursor IDs, never token hashes or bearer tokens.

## Browser variables, confirmation and recovery

The independent Zod contract has no database runtime import. Frozen `ACCOUNT_SESSION_BROWSER_LIMITS` has pageSize30,requestBytes2048,responseBytes16384,timeoutMs15000. AccountSessionList,Item,Intent,Result are minimized strict schema-derived types. Snapshot validation binds account, current/other unique IDs, bounded30 rows, exact decimal count, ISO times and bounded cursor. It rejects secret/extra fields or current-session duplicates. Receipt validation binds account/request/target exactly and valid revokedAt; response envelope permits only data and optional strict replay metadata.

`makeAccountSessionIntent` requires a different currently displayed target and freezes the exact request. `accountSessionLookupPath` includes only account/request IDs. `runAccountSessionIntent` makes one POST or one explicit GET with same-origin credentials,no-store,redirect:error,abort checks before send/after bounded body parse and no automatic retries. Unexpected status/shape/size/fatal UTF-8 fails. Error guidance is fixed locally, not arbitrary remote message text. Abort/timeout does not prove transaction rollback.

`AccountSessionsSection` alone holds server actor context. It validates the minimized projection before passing snapshot to the client. Authentication failures offer sign-in; other load/shape/cursor failures offer newest-list reload without exposing errors or breaking unrelated settings. JSX rendering is outside its data-loading try/catch, satisfying React's error-boundary rule; it does not claim to catch descendant render failures.

`AccountSessionsPanel` keys the editor by accountId plus current.sessionId. React-local selected/confirmed/intent/result/pending/error represent one reviewed target, explicit confirmation, original frozen request, historical outcome, busy state and guidance. retained pins intent synchronously before transport; mounted prevents post-unmount updates; gate is form-local. Its active controller/timer block overlap, cancel at15seconds and invalidate late results; old finish cannot clear a newer operation. Different current/account identity remounts/cancels. router.refresh updates current list after confirmation but does not silently discard the original intent.

No mutation is sent by Review selection or checkbox alone. Sign out selected session requires both explicit selected target and checked confirmation. reviewHeading and selectionTrigger are local DOM refs: opening review focuses its heading so the user reaches a confirmation below a long list; Cancel returns focus to the originating button. Neither ref is authority. Once sent, selection remains locked; Check original sign-out result performs GET only. Receipts are historical and do not certify later sign-ins. Reload/paging/leaving loses the in-memory request key; server receipts remain but no unknown-key recovery is promised. No local/session storage or new cookie persists the request. Scoped CSS uses wrapping cards/times,bordered44px controls,explicit disabled state and3px keyboard focus. Names/IDs/times render as escaped text.
