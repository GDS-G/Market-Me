## Read path and authority

`/campaigns/[id]` is a server-rendered observation of the current workspace's saved Campaign. Authentication and active membership precede the read. The UUID path normalizes lowercase; an optional workspaceId query must match the current selection. Unknown keys, arrays/duplicates, malformed or foreign hints fail closed before Campaign reads. Returned Campaign id/workspace and protected receipt lineage are checked again. Missing/inconsistent rows do not render foreign data.

The page reads only the scoped Campaign and member-readable finalization provenance, not all candidate packages, profiles, Destinations or connections. It does not mutate Campaign state or trigger provider/workflow work. Existing authentication may update session bookkeeping. These separate reads are observations, not a transaction-wide snapshot or eligibility lease; later activation still uses the 1.54 fresh review, version/grant hints and transaction checks.

The six workspace roles remain unchanged. Owner/admin/editor see explicit links to advanced editing and, for an observed published non-draft-only unarchived unprotected version, activation review. Approver/analyst/viewer and unknown roles receive read-only presentation. No mutation handler or form exists on the inspection page. Archived campaigns offer no new action links. Protected plans link to their original finalization receipt instead of bypassing its controls or existing-run guidance.

The campaign list now links to inspection for every role. Its Published steps value uses currentVersion only; it no longer pairs a published version label with an unpublished draft's step count. `campaignInspectionPath` validates and normalizes both UUIDs and includes workspaceId as a selection hint, not authority. A nonwriter reaching the old edit route redirects to scoped inspection before Campaign/provenance/editor-picker reads. Direct new-Campaign navigation by a nonwriter explains writer access before candidate repository calls. Writer creation and protected writer editing remain existing flows.

Hiding links does not add transaction authorization to legacy create/save/publish APIs. Their existing writer checks and transaction/optimistic-concurrency limitations are unchanged and must be audited independently. The new activation boundary remains current-member locked. Do not describe this display increment as new rights, a permission token or a remedy for all concurrent membership changes.

## Presentation contracts, collections and variables

`CampaignInspection` receives one scoped `StoredCampaign` in the server render graph. `CAMPAIGN_PLAN_SECTIONS` is a readonly two-entry tuple describing currentVersion/published and draftVersion/draft separately. A version with another campaignId or an unexpected status renders an unavailable/changed notice, not its contents. An absent version has an explicit empty state. Campaign name/description are current record labels; existing runs retain their governing version.

`CAMPAIGN_INSPECTION_LIMITS` freezes steps=100, dependencies=20 and goals=20. These are display caps, not SQL fetch limits: the existing Campaign loader still hydrates its stored versions. Full counts and honest coverage notices accompany bounded slices; no truncated summary claims to be a complete activation review. `autonomousLabels` maps all eight autonomy values to configured-policy wording, retaining review for unsupported confidence/history waivers. `words` replaces underscores only and React escapes labels. No arbitrary HTML is used.

`VersionSummary` displays version identity/number, objective, configured approval mode, timezone, information depth/promotion and counts/presence of bound references. It renders ordered step names/keys/capability, operation, saved schedule, dependency keys and completion delay, execution preferences, explicit approval flag, max attempts, timeout and optionality. No false flag is called a policy waiver. Missing optional fields use the same stored-plan defaults as insertion: manual_handoff operation, immediate schedule, 3 attempts, 300-second timeout, 0 dependency delay. These are saved settings, not provider capability, rights or approval validation.

`campaignInspectionTiming` reports immediate/dependency/exact-time/preferred-window settings without calculating new dates or claiming on-time completion. Captured timestamp strings retain their precision and offsets. A window is inclusive-start/exclusive-end for supported request starts, not provider completion; incomplete times say so. Recurring/evergreen/conditional/follow-up enums are explicitly saved-only, not executed schedules. Other route combinations may also remain unsupported; the summary does not replace activation validation.

Success criteria retain their existing parsed numeric values through String without conversion, arithmetic, localization or added rounding. This does not promise greater numeric precision than the existing source model. Value goals keep their own currency; count goals stay recorded event targets. Saved targets are not measurements, attribution or financial outcomes. The current successAction maps pause/notify_only without enqueueing either.

Arbitrary context, step inputs/outputs/conditions, provider/account payloads and credentials are deliberately omitted. Bound references are counts/presence, not invented friendly labels or validation claims. There is no client editor state, sessionStorage key, fetch loop, browser mutation, new process-global mutable result or server cache. Page-local canWrite/archived/published/canReviewActivation only choose navigation; existing handlers authenticate independently. CSS cards/fact grids wrap identifiers and collapse on narrow viewports; development and production desktop/mobile acceptance is verified.
