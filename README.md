# Market Me

Market Me is a universal content-to-campaign operating system. It monitors customer-selected content locations, builds evidence-backed Content Packages, and coordinates approval-aware marketing campaigns across connector capabilities.

## Current build (1.23.0 verified local preview)

The **1.23.0 preview** adds exact-reviewed-preview finalization: one approved prepared draft becomes an approval-required executable draft in the same Campaign, without JSON authoring. The finalizer does not publish, activate, approve or send. Immutable receipt provenance and a raw, full-precision preview fingerprint protect later activation and new/retry publication admission. Explicit publish/activate controls remain separate, and finalized plans are read-only. Reviewed source is published on main after all 1,405 tests and clean Linux CI passed; authenticated browser, production build/smoke and native packaging passed separately. Exact evidence is tracked in [Releases](docs/RELEASES.md) and [cloud CI](docs/CI.md). Release 0.66 adds bounded credential verification. Release 0.67 adds bounded workspace-private provider model inventory without making discovered models executable. Release 0.68 adds workspace-governed capability-evidence candidates without activating or routing them. Release 0.69 snapshots approved candidates into tenant-scoped deployment staging while keeping them unavailable and outside routing. Release 0.70 binds exact source-verified hosted pricing evidence to that staging record while preserving the same fail-closed execution boundary. Release 0.71 stages a source-hashed server-owned invocation contract against current deployment and pricing evidence while implementation and health remain unavailable. Release 0.72 records short-lived non-generative provider-reachability evidence without making the invocation implementation healthy or routable. Invocation implementation, routing activation, provider execution, usage reconciliation, and settlement remain later work.

Release 1.1 adds the production S3-compatible immutable-object adapter and removes four divergent filesystem constructions. It is the application storage portability boundary, not a claim that backup/recovery is complete: operators must still configure and test bucket versioning, encryption, retention/replication, access logging, and PostgreSQL/Temporal restore procedures. Email delivery/outcome reconciliation, broader owned-channel connectors, automated opportunity discovery/outreach, cross-platform signed desktop delivery, production malware operations, and full hosted-model execution/evaluation promotion remain tracked work.

## Start locally

Prerequisites: Node.js 22+, npm 10+, and Docker Desktop.

```powershell
npm install
npm run db:up
$env:DATABASE_URL='postgres://market_me:market_me_local@localhost:5432/market_me'
npm run db:migrate
npm run malware:up
$env:MALWARE_SCANNER='clamav'
npm run workflow:up
npm run dev
# In a second terminal after configuring connector credentials:
npm run worker
# In another terminal for durable campaigns:
npm run workflow-worker
```

Open `http://localhost:3000`. Run the full verification suite with `npm run check`.

For desktop-companion development, install the Tauri v2 prerequisites for the target operating system, then use `npm run companion:dev`. `npm run companion:bundle` creates the Windows NSIS installer on a configured Windows build host.

Copy `.env.example` to `apps/web/.env.local` for web runtime configuration. The local database-only file can omit connector secrets. Never commit real credentials.

Operational incident webhooks remain unavailable unless the deployment sets a separate 32-byte base64 `AI_OPERATIONAL_ALERT_ENCRYPTION_KEY` and an exact comma-separated `AI_OPERATIONAL_ALERT_ALLOWED_HOSTS` list. `AI_OPERATIONAL_ALERT_BATCH_SIZE` defaults to 25. Do not reuse connector-token or hosted-provider credential keys for this boundary.

Hosted-text execution also fails closed unless `AI_PROVIDER_EXECUTION_ENABLED=true`, `AI_PROVIDER_CREDENTIAL_ENCRYPTION_KEY` is a valid 32-byte base64 AI vault key separate from connector and alert keys, the selected provider credential/evidence is current, an administrator has opened a time-limited workspace window, and its provider circuit is closed. The AI vault key encrypts both provider credentials and generated output envelopes in this release. Keep the deployment flag false by default; the execute route never returns plaintext and never retries a claimed provider request.

For local development, keep `MEDIA_OBJECT_STORE=filesystem` and point every process at the same `MEDIA_STORAGE_ROOT`. Production fails closed unless `MEDIA_OBJECT_STORE=s3`; configure one shared bucket/region/prefix through the `MEDIA_S3_*` variables and prefer the AWS SDK workload identity/credential chain over static keys. Generate a separate `MEDIA_ACCESS_SIGNING_KEY` of at least 32 random bytes for short-lived preview URLs; never reuse the connector encryption key.

Release 0.95 treats prior bare `cleared` asset flags as unreviewed. An original image must have a recorded owner, source and proof references, current worldwide commercial and derivative permission, an allowed publication channel, reviewer identity/time, and a positive rights revision. Derivatives inherit the original's rights decision. Saved channel previews capture that revision and become stale if rights are changed, withdrawn, future-dated, expired, or no longer permit the provider.

Release 0.96 treats a legacy `clean` malware flag without engine/time/revision evidence as `not_configured`. The worker uses `MALWARE_SCANNER=clamav` plus `CLAMAV_HOST`, `CLAMAV_PORT`, and `CLAMAV_TIMEOUT_MS` to stream bytes to clamd before immutable storage. `npm run malware:up` starts the pinned local ClamAV 1.5.3 profile on loopback only; never expose port 3310 to an untrusted network because clamd TCP has no authentication or encryption. An unconfigured or failed scanner may preserve a quarantined review asset but can never authorize package approval, preview attachment, Campaign activation, or provider execution.
